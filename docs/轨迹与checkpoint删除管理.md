# 轨迹与checkpoint删除管理

更新：2026-11-02（Asia/Shanghai）。用户已确认：删除轨迹仅删除本地档案，服务器训练经验和模型保留。删除功能不用于撤销模型已经学习过的数据。

## GUI入口

在8888打开“轨迹档案”。页面包含轨迹列表、本地轨迹回收站、服务器checkpoint/命名版本清单及其回收站。checkpoint清单按需刷新，网络与磁盘扫描不进入控制循环。

| 对象 | 删除范围 | 保留内容 |
| --- | --- | --- |
| 本地轨迹 | 所选UUID目录内HDF5、元数据、曲线等整条本地档案 | 服务器reviewed_episodes、采集批次、模型参数和训练计数全部保留 |
| GUI-RL保存点 | 所选数字step目录和同step的review_state JSON作为一组 | 其他保存点、W&B身份、服务器训练经验、客户端轨迹保留 |
| RTC-SFT保存点 | 所选数字step完整目录 | 其他step及已经登记的硬链接版本保留；被初始化配置引用时拒绝删除 |
| 命名模型版本 | models/releases下选定版本的整包，包括模型硬链接和资产/配置快照 | 原run保存点和其他命名版本保留 |

原普通SFT来源只读，不开放任意文件路径删除；网页只能提交清单中的来源ID和对象名。不能单独删除review_state、经验目录或训练配置。

## 删除、恢复与永久删除

1. **删除**：点击列表“删除”，确认完整对象身份和影响后移入同目录`.trash/<回收ID>/payload/`。该步骤可以恢复，不释放磁盘空间。
2. **恢复**：在对应回收站点击“恢复”，回到原位置；同名文件已存在时拒绝覆盖。checkpoint与同step辅助状态一起恢复。
3. **永久删除**：在回收站点击“永久删除”，重新输入完整32位回收ID确认。不可恢复；保留很小的receipt确认记录供审计，不保留payload；不提供自动清空或批量默认清理。存在其他硬链接时，不保证释放整份模型的空间。

本地轨迹的录制、待审核、已提交未确认、待整批处理状态不能删除。活动客户端会话和手动机械臂操作期间不开放删除/恢复，防止与控制链争用；先正常结束，不会自动急停或停止任务来执行删除。

## checkpoint保护与续训影响

- 服务器每次变更前重新检查本GUI管理的任务身份及配置里的模型端口；正在训练、推理或独立CLI仍占用端口时拒绝操作，不自动终止进程。
- base_weights/rtc_weights仍指向所选目录时拒绝删除；先显式选择其他基线并修改配置，再重新刷新。历史训练配置快照的引用也会保留保护，避免无意破坏恢复依赖。
- 删除最新保存点后，GUI续训回退到剩余的最新完整点；删完所有点则该实验不能续训或从原目录推理。恢复删除的点后重新出现在列表。
- 训练经验文件不会随checkpoint删除。以后从较早模型恢复时，原有恢复逻辑会隔离超出保存step的经验；这不是删除数据或撤销已发生训练。
- 删除原保存点不会破坏已经登记的硬链接命名版本；删除命名版本也不删除原run。硬链接不是独立备份，必须遵守[模型权重使用约定](模型权重管理与使用.md)。
- 保护依据是本GUI管理器和已知配置端口，不承诺识别任意外部进程的模型依赖；外部程序使用相同模型时应先结束其使用，再清理文件。

## 服务端只读清单

在4090查看管理清单，不加载模型或连接机器人：

```bash
cd /data/gcj_data/rl/real_time_expo_ft/code
uv run --locked python -m piperx_expo.server.gui_service storage
```

日常操作使用GUI确认，不手工拼接路径删除。服务器变更在原管理锁下执行，原始模型、经验和现场配置不会被任意路径参数覆盖。移动失败会尝试回滚同组文件，未完整提交的回收记录不显示成成功；磁盘异常导致回滚也失败时需保留现场并检查receipt/payload，不能继续猜测恢复。

## 验证边界

删除测试仅使用自动生成的临时合成轨迹/checkpoint；不删除任何已有真实数据。覆盖回收/恢复/永久删除确认、路径穿越/符号链接、同名恢复拒绝、分组移动失败回滚、活动会话/端口拒绝、初始化引用保护、最新点回退和硬链接版本保留。部署和验证结果见[本轮记录](历史/设计/2026-11-02_轨迹与checkpoint删除管理.md)。
