# Real-Time EXPO-FT 浏览器客户端使用说明

更新：2026-11-01。GUI负责执行、轨迹留档与复核；模型推理和强化学习仍在4090上进行。原命令行入口完整保留。

## 选择运行方式

| 方式 | 4090配置 | piperx入口 | 回合结束后的处理 |
| --- | --- | --- | --- |
| 原命令行 | `configs/server/rotating_square.h30.yaml` | `scripts/client.sh` | 原自动检测与收录，终端输入READY复位 |
| 浏览器逐条复核（默认） | `configs/server/rotating_square.gui.yaml` | `scripts/gui.sh` | 等待人工选择标签及是否加入经验，再回传服务器 |
| 浏览器自动收录 | 同上GUI配置 | 同上GUI入口；在“会话参数”切换 | 自动提交检测结果并收录，下一条仍须人工复位确认 |

GUI配置中的 `episode_review: true` 选择独立的复核驱动；原配置不包含此开关，仍运行原上游训练循环。两种服务器占用同一8103端口，每次只启动一种。GUI不会静默接入旧服务器，旧CLI也会拒绝GUI专用协议。

**数据会直接回传**：动作由服务器逐步下发，实测状态和双相机RGB通过现有有线WebSocket逐步返回服务器。逐条复核模式只是推迟经验入池和更新，不需要采集后手工上传或转换整条文件。复核结果另行回传，服务器确认后界面才显示“已加入经验”或“已拒收”。

## 先体验界面（不动机器人、不训练）

在piperx上：

```bash
cd /home/cv/gcj/rl/baseline/realtime_expo_ft
bash scripts/gui.sh --config configs/client/gui.mock.yaml
```

用这台电脑的浏览器打开 `http://127.0.0.1:8767`，点击“模拟体验”→“现场就绪，归位并开始”。模拟画面为灰色合成图，界面明确标为模拟环境；约46步触发示例自动成功。可手动改为失败、取消加入经验并提交，档案标记“模拟已复核”，不会声称已进入真实学习器。

在“会话参数”将最大步数改为12，下一条会在成功触发前结束。可切换“自动收录”，观察结束后直接保存自动结果。更改最大步数和收录模式都只影响下一条，不改变正在执行或待复核的回合。

## 固定归位与edit选项

真机每条回合复位时，先人工复位方块并确认路径安全，点击“现场就绪，归位并开始”后按`configs/client/home.openpi.yaml`执行固定六关节归位。等待反馈到位后才开始策略；归位中可停止，30秒超时或异常会锁定。夹爪不会自动张开。详见[表示与归位合同](数据表示与固定归位核对_20261101.md)。

两份旋转方块服务器YAML当前按用户最新要求设为`edit_action_xyzg: true`：只编辑XYZ和夹爪，屏蔽edit的RPY旋转。设false可选全7维编辑；省略字段时也默认true。基础VLA始终预测完整动作。改变模式后使用独立RL run及checkpoint目录。

## 真机运行

先按[真机强化学习快速开始](真机强化学习快速开始.md)完成RTC-SFT、最终权重核验、原采集预检、成功检测正负例、工作空间、保持/单步与模型延迟验收。已有RTC-SFT仍在运行时，不另启大模型RL。

现在只需要在机器人电脑启动下面的GUI，不再需要手工登录4090、创建tmux或输入服务器启动命令。`rotating_square.calibrated.yaml`已配置已有的有线SSH别名`gh4090piper-wired`，服务器仍使用`rotating_square.gui.yaml`和原online W&B设置。

点击“启动服务器 RL”时自动保存配置快照，并将run_name追加时间和随机后缀，每次创建独立RL run，不覆盖旧结果。`rtc_weights`仍使用原batch32 RTC-SFT的4000步参数，不自动替换权重。端口已占用、GPU有其他计算进程或路径校验失败时拒绝启动，错误和日志显示在页面。总预算仍为4000动作步，拒收也消耗采集预算；单条最大步数1～2000。

机器人现场，在退出其他占用CAN/相机的程序后：

```bash
cd /home/cv/gcj/rl/baseline/realtime_expo_ft
bash scripts/gui.sh \
  --config configs/client/rotating_square.calibrated.yaml \
  --record-dir /home/cv/gcj/rl/data/realtime_expo_ft/gui_episodes \
  --allow-motion
```

打开 `http://127.0.0.1:8767`：

1. 检查右上角为“真机”，确认参数、成功检测阈值及学习器地址。
2. 在“4090训练服务器”面板点击“启动服务器 RL”。页面显示模型初始化、可连接、异常或退出状态；展开“服务器日志”可查看进度。
3. 勾选现场运动确认，点击“连接学习器”；可在模型初始化期间连接并等待，不会因此立即运动。
4. 等待现场复位提示，人工复位物体并确认归位路径安全，再点击“现场就绪，归位并开始”。机械臂会执行固定关节归位，反馈到位后才开始策略。
5. 观察双相机、曲线和步数；可“结束本条并复核”提前截断。逐条复核时选择标签、是否收录及备注，然后提交。
6. 等服务器ACK及下一次复位请求，再开始下一条。结束本次实验时点击“停止服务器 RL”或顶部“停止并锁定”：先停止本机设备，再结束专属远端训练。
7. 需要新实验时等待服务器停止完成，再点“启动服务器 RL”，重新检查现场并勾选运动确认，连接学习器建立全新会话。GUI进程可继续使用；旧的机器人设备会话保持锁定，不复用已停止硬件对象。

自动收录模式无需第5步，会使用自动标签立即提交；自动成功为奖励1，未检出成功为奖励0。“未检出成功”不等同人工确认失败。**已提交、尤其已用于训练的轨迹不能在GUI中事后改标或撤回**；需要人工控制标签或收录时，提前切换逐条复核。

## 回放与参数

- “轨迹档案”展示原始自动结果、人工标记和最终收录状态。回放支持双相机逐帧、XYZ/夹爪曲线和HDF5下载；回放时复核按钮禁用，避免误改当前回合。
- 界面中的图像是模型实际使用的224×224 RGB输入，不是原相机全分辨率录像。曲线是实测反馈，训练动作则是经过安全校验后实际下发的绝对目标。
- 可修改下一条最大步数、收录模式；服务器地址/端口仅会话启动前可改。频率、指令、成功阈值、工作空间、速度与步长边界在界面只读，需修改现场YAML并重新验收。
- 会话参数保存在每条轨迹的配置快照中；界面修改不会覆盖YAML，重启后重新读取配置文件。
- 最大步数很短且未人工判为终止失败时，原算法会过滤跨截断的critic窗口；不建议将12步演示预算用于正式训练吞吐评估。

## 停止、异常与恢复

“停止并锁定”会关闭控制并停止设备，本条未完成的轨迹标为中断，不进入经验；已提交但尚无ACK的条目仍显示待确认。断线不重发动作，不自动重连继续执行。真机运行中浏览器心跳中断超过5秒也会停止，控制端原有动作看门狗继续生效。硬件急停继续按现场规范使用。

两种停止按钮都会先停止本机运动，再通过SSH向本GUI管理的远端进程组发送中断信号；超时后升级终止，绝不使用pkill或停止其他任务。关闭GUI进程也会尝试停止该专属服务；仅关闭浏览器页面时，运行/归位阶段的心跳超时会触发停止。SSH失败时显示“状态未确认”，不能视作服务器已停止。

停止会保留日志、轨迹和已完成checkpoint，但不承诺强制中断时另存最后一次更新。GUI启动始终是新run，不自动续训；需要专家手动恢复时，使用该次自动生成的配置快照及对应checkpoint：

```bash
bash scripts/server.sh rl --config runtime/gui_server/<本次ID>/experiment.yaml --resume
```

只恢复模型已保存步数以前的已收录经验，之后的服务端轨迹隔离到 `unrestored_episodes/`；客户端档案原样保留。GUI目录不能混作原CLI运行目录，CLI检查点也不能直接冒充GUI训练状态。模型checkpoint与复核状态文件必须成套完成保存。

GUI默认只监听本机。如果从自己的电脑查看piperx，使用同端口SSH转发：

```bash
ssh -N -L 8767:127.0.0.1:8767 piperx
```

随后本机浏览器打开 `http://127.0.0.1:8767`。控制页面仅接受同源、带会话令牌的操作。不要把控制服务公开到公网；此远程访问仍要求有人现场复位与监护。端口占用时使用GUI的 `--port` 并把转发两端改为相同端口。

## 归档与验证边界

每条轨迹保存为 `<record-dir>/<UUID>/episode.hdf5` 和 `metadata.json`，中断写入可能保留 `episode.partial.hdf5`。默认记录目录为项目内被Git忽略的 `runtime/gui_episodes`；正式采集建议使用上面独立数据路径。两路224 RGB未压缩，约0.30MB/观测，2000步约0.60GB，需留出磁盘余量。

已完成模拟RPC、标签覆盖、拒收、自动收录、恢复、HTTP来源校验及浏览器操作验证。没有执行真实机器人轨迹、实际在线RL更新或真机吞吐验证。详细数据核查结论见[数据采集、转换与传输检查](真机RL数据采集转换传输检查.md)。

远程管理设计与验收边界见[GUI远程训练管理](GUI远程训练管理.md)。
