# Real-Time EXPO-FT 浏览器客户端使用说明

更新：2026-11-02。GUI负责执行、轨迹留档与复核；模型推理和强化学习仍在4090上进行。原命令行入口完整保留。

## 选择运行方式

| 方式 | 4090配置 | piperx入口 | 回合结束后的处理 |
| --- | --- | --- | --- |
| 原命令行 | `configs/server/rotating_square.h30.yaml` | `scripts/client.sh` | 原自动检测与收录，终端输入READY复位 |
| 浏览器逐条复核（默认） | `configs/server/rotating_square.gui.yaml` | `scripts/gui.sh` | 等待人工选择标签及是否加入经验，再回传服务器 |
| 浏览器自动收录 | 同上GUI配置 | 同上GUI入口；在“会话参数”切换 | 自动提交检测结果并收录，下一条仍须人工复位确认 |

GUI配置中的 `episode_review: true` 选择独立的复核驱动；原配置不包含此开关，仍运行原上游训练循环。两种服务器占用同一8103端口，每次只启动一种。GUI不会静默接入旧服务器，旧CLI也会拒绝GUI专用协议。

**数据会直接回传**：动作由服务器逐步下发，实测状态和双相机RGB通过现有有线WebSocket逐步返回服务器。逐条复核模式只是推迟经验入池和更新，不需要采集后手工上传或转换整条文件。复核结果另行回传，服务器确认后界面才显示“已加入经验”或“已拒收”。

## 先体验界面（不动机器人、不训练）

在piperx上：

```bash
cd /home/cv/gcj/rl/baseline/realtime_expo_ft
bash scripts/gui.sh --config configs/client/gui.mock.yaml
```

用这台电脑的浏览器打开 `http://127.0.0.1:8767`，点击“模拟体验”→“现场就绪，归位并开始”。模拟画面为灰色合成图，界面明确标为模拟环境；约46步触发示例自动成功。可手动改为失败、取消加入经验并提交，档案标记“模拟已复核”，不会声称已进入真实学习器。

在“会话参数”将最大步数改为12，下一条会在成功触发前结束。可切换“自动收录”，观察结束后直接保存自动结果。更改最大步数和收录模式都只影响下一条，不改变正在执行或待复核的回合。

## 指定网页端口

默认网页端口8767被占用时，在机器人电脑指定其他端口，例如8768：

```bash
bash scripts/gui.sh \
  --config configs/client/rotating_square.calibrated.yaml \
  --record-dir /home/cv/gcj/rl/data/realtime_expo_ft/gui_episodes \
  --allow-motion --port 8768
```

打开[GUI页面](http://127.0.0.1:8768)。远程访问同步改转发端口：`ssh -N -L 8768:127.0.0.1:8768 piperx`。这个参数只改变网页端口，不修改模型通信8103；不要为解决网页占用而启动第二个真实控制会话。

## 固定归位与edit选项

真机每条回合复位时，先人工复位方块并确认路径安全，点击“现场就绪，归位并开始”后按`configs/client/home.openpi.yaml`执行固定六关节归位。等待反馈到位后才开始策略；归位中可停止，30秒超时或异常会锁定。夹爪不会自动张开。详见[表示与归位合同](历史/数据与控制/2026-11-01_数据表示与固定归位核对.md)。

两份旋转方块服务器YAML当前按用户最新要求设为`edit_action_xyzg: true`：只编辑XYZ和夹爪，屏蔽edit的RPY旋转。设false可选全7维编辑；省略字段时也默认true。基础VLA始终预测完整动作。改变模式后使用独立RL run及checkpoint目录。

## 归位起点越界时

确认归位前只读检查法兰XYZ与关节起点。按现场批准，归位起点范围为X∈[-0.10,1]m、Y∈[-1,1]m、Z∈[-0.10,1]m，起点关节限位容差0.06rad；策略执行工作区和目标到位容差保持原值。起点越界时页面显示实测坐标和允许范围，保持等待现场复位，不发送归位目标，也不让服务器因该拒绝退出。现场核对姿态、坐标系和home_config后，可再次点击确认；运动前仍会重复完整检查。不要仅为消除提示扩大工作空间。反馈过期、控制故障或实际归位失败仍停止并锁定。

GUI服务器日志收尾最多等待15秒（wandb_finish_timeout_s）；网络不通时未上传数据保留本地，异常退出在W&B标为失败。

## 独立机械臂按钮

停止旧学习器连接会话，完成现场预检并勾选运动确认后，可分别操作：

- **恢复使能**：恢复无其他错误的急停状态、CAN控制和电机使能，不读取关节/法兰，不做归位范围判定，也不发送位置目标或执行固定归位。点击后最多3秒有界重试；只对急停状态发送一次控制器reset，不自动清除碰撞等其他故障。只有六电机与控制器正常/CAN控制均反馈确认，页面才显示恢复完成；电机使能标志为True而控制器仍急停/待机时，会显示具体未恢复原因。实际支撑能力仍需现场验收。
- **保持位置**：读取一次当前法兰位置并原样发送为目标，不做归位范围、反馈时效、关节限位或使能/模式前置判断，不自动使能/复位。CAN刚连接只等待首帧；完全没有位姿数据时会提示无法读取当前位置，不猜测位置。
- **取消保持位置**：释放本软件保持会话，不发送失能、急停、复位或新位置指令，不恢复旧目标、不自动运动。硬件继续最后位置控制，允许后续命令接管；这不等于拖动模式。
- **机械臂复位**：独立执行原固定六关节归位；相机、起点/目标、低速、到位等原检查保留，不启动学习器或轨迹。

操作进行中禁止重入；正常交接保留使能。顶部“急停 · Esc”或浏览器失联5秒会停止并锁定后续控制。训练回合原有现场确认和自动归位流程保留。本轮只验证软件与模拟设备，没有点击真实机械臂操作。

## 真机运行

先按[真机强化学习快速开始](真机强化学习快速开始.md)完成RTC-SFT、最终权重核验、原采集预检、成功检测正负例、工作空间、保持/单步与模型延迟验收。已有RTC-SFT仍在运行时，不另启大模型RL。

现在只需要在机器人电脑启动下面的GUI，不再需要手工登录4090、创建tmux或输入服务器启动命令。`rotating_square.calibrated.yaml`已配置已有的有线SSH别名`gh4090piper-wired`，服务器仍使用`rotating_square.gui.yaml`和原online W&B设置。

选择“新建训练”时自动保存配置快照，并将run_name追加时间和随机后缀，创建独立RL run。选择历史实验则从其最近完整checkpoint接续原训练目录、W&B身份、经验和更新计数；不会创建新的模型实验。`rtc_weights`仍使用原batch32 RTC-SFT的4000步参数，不自动替换权重。端口已占用、GPU有其他计算进程或路径校验失败时拒绝启动，错误和日志显示在页面。总预算仍为4000动作步，拒收也消耗采集预算；单条最大步数1～2000。

机器人现场，在退出其他占用CAN/相机的程序后：

```bash
cd /home/cv/gcj/rl/baseline/realtime_expo_ft
bash scripts/gui.sh \
  --config configs/client/rotating_square.calibrated.yaml \
  --record-dir /home/cv/gcj/rl/data/realtime_expo_ft/gui_episodes \
  --allow-motion --port 8888
```

打开 `http://127.0.0.1:8888`：

1. 检查右上角为“真机”，确认参数、成功检测阈值及学习器地址。
2. 在“4090训练服务器”面板选择“新建训练”或可续训的历史实验，再点击启动按钮。页面显示模型初始化、可连接、异常或退出状态；展开“服务器日志”可查看进度。
3. 勾选现场运动确认，点击“连接学习器”；可在模型初始化期间连接并等待，不会因此立即运动。
4. 等待现场复位提示，人工复位物体并确认归位路径安全，再点击“现场就绪，归位并开始”。机械臂会执行固定关节归位，反馈到位后才开始策略。
5. 观察双相机、曲线和步数；可“结束本条并复核”提前截断。逐条复核时选择标签、是否收录及备注，然后提交。
6. 等服务器ACK及下一次复位请求，再开始下一条。结束本次实验时点击“停止服务器 RL”或顶部“急停 · Esc”：先停止本机设备，再结束专属远端训练。
7. 等待服务器停止完成后，可新建实验，也可选择已有实验继续。重新检查现场并勾选运动确认，再连接学习器；机器人建立新的CAN会话，相机流继续复用。

自动收录模式无需第5步，会使用自动标签立即提交；自动成功为奖励1，未检出成功为奖励0。“未检出成功”不等同人工确认失败。**已提交、尤其已用于训练的轨迹不能在GUI中事后改标或撤回**；需要人工控制标签或收录时，提前切换逐条复核。

## 常驻相机、放宽动作与续训

- 真机GUI启动即开启两路相机，空闲、归位、回合间复核、停止和重连期间持续缓存最新帧并提供预览。只在归位完成、rollout开始时创建EpisodeRecorder，保存初始观测和后续动作/观测；预览不写轨迹文件。退出GUI才关闭相机。原CLI相机随进程/环境关闭，同一环境的多次reset不重开相机。
- 正式`rotating_square.calibrated.yaml`按现场授权对齐参考客户端：策略SDK速度90%，单目标到当前反馈的位移上限0.3m，RPY每轴最短角差上限0.5rad，夹爪目标0～0.10m且允许一次全范围张合。归位仍10%，工作空间、反馈新鲜度、看门狗和SDK角度格式检查保留。90%是SDK百分比，不是末端米/秒。
- 急停按钮始终位于页面顶部；Esc在该控制页面具有键盘焦点时生效，包括输入框、历史和设置页。请求不弹确认框，不等待相机或远程训练结束才停止本机；保持效果和硬件制动距离仍须现场验收。
- 在服务器面板选择历史实验，列表显示保存步数和更新次数；不可恢复的实验显示原因。填写“续训追加动作步数”后启动；总预算取原预算与“保存步数+追加步数”的较大值。配置与数据/模型资产沿用该实验快照，不能通过网页换权重或工作目录。
- 仅支持由本GUI管理的RL实验：必须有完整Orbax checkpoint、同一步`review_state_<step>.json`和原`wandb_id.txt`。只有日志、W&B记录或已ACK轨迹而没有模型checkpoint，不能还原未保存的模型。保存点之后的经验按原逻辑隔离，客户端档案保留。
- 新建GUI实验配置改为每个完整回合更新后保存checkpoint，保存期间会有额外I/O等待；启动/停止管理日志仍每次独立保留。旧实验续训沿用旧快照保存频率。停止不等待额外强制模型保存，也不恢复被中断的半条rollout。

## 回放与参数

- “轨迹档案”展示原始自动结果、人工标记和最终收录状态。回放支持双相机逐帧、XYZ/夹爪曲线和HDF5下载；回放时复核按钮禁用，避免误改当前回合。
- 界面中的图像是模型实际使用的224×224 RGB输入，不是原相机全分辨率录像。曲线是实测反馈，训练动作则是经过安全校验后实际下发的绝对目标。
- 可修改下一条最大步数、收录模式；服务器地址/端口仅会话启动前可改。频率、指令、成功阈值、工作空间、速度与步长边界在界面只读，需修改现场YAML并重新验收。
- 会话参数保存在每条轨迹的配置快照中；界面修改不会覆盖YAML，重启后重新读取配置文件。
- 最大步数很短且未人工判为终止失败时，原算法会过滤跨截断的critic窗口；不建议将12步演示预算用于正式训练吞吐评估。

## 停止、异常与恢复

顶部“急停 · Esc”或页面获得键盘焦点时按Esc，会先锁定后续目标发送，再用新鲜法兰反馈覆盖旧目标并保持使能；反馈缺失、过期或保持发送失败时退回SDK阻尼急停。此后关闭CAN和学习器连接，本条未完成的轨迹标为中断，不进入经验；已提交但尚无ACK的条目仍显示待确认。断线不重发动作，不自动重连继续执行。真机运行中浏览器心跳中断超过5秒也会停止，控制端原有动作看门狗继续生效。硬件急停继续按现场规范使用。停止请求不会自动恢复使能或重放旧动作。

两种停止按钮都会先停止本机运动，再通过SSH向本GUI管理的远端进程组发送中断信号；超时后升级终止，绝不使用pkill或停止其他任务。关闭GUI进程也会尝试停止该专属服务；仅关闭浏览器页面时，运行/归位阶段的心跳超时会触发停止。SSH失败时显示“状态未确认”，不能视作服务器已停止。

停止会保留日志、轨迹和已完成checkpoint，但不承诺强制中断时另存最后一次更新。GUI支持显式选择历史实验续训，不会自动选择某次实验。命令行也可使用该次自动生成的配置快照及对应checkpoint恢复：

```bash
bash scripts/server.sh rl --config runtime/gui_server/<本次ID>/experiment.yaml --resume
```

只恢复模型已保存步数以前的已收录经验，之后的服务端轨迹隔离到 `unrestored_episodes/`；客户端档案原样保留。GUI目录不能混作原CLI运行目录，CLI检查点也不能直接冒充GUI训练状态。模型checkpoint与复核状态文件必须成套完成保存。

GUI默认只监听本机。如果从自己的电脑查看piperx，使用同端口SSH转发：

```bash
ssh -N -L 8767:127.0.0.1:8767 piperx
```

随后本机浏览器打开 `http://127.0.0.1:8767`。控制页面仅接受同源、带会话令牌的操作。不要把控制服务公开到公网；此远程访问仍要求有人现场复位与监护。端口占用时使用GUI的 `--port` 并把转发两端改为相同端口。

## 归档与验证边界

每条轨迹保存为 `<record-dir>/<UUID>/episode.hdf5` 和 `metadata.json`，中断写入可能保留 `episode.partial.hdf5`。默认记录目录为项目内被Git忽略的 `runtime/gui_episodes`；正式采集建议使用上面独立数据路径。两路224 RGB未压缩，约0.30MB/观测，2000步约0.60GB，需留出磁盘余量。

已完成模拟RPC、标签覆盖、拒收、自动收录、恢复、HTTP来源校验及浏览器操作验证。没有执行真实机器人轨迹、实际在线RL更新或真机吞吐验证。详细数据核查结论见[数据采集、转换与传输检查](真机RL数据采集转换传输检查.md)。
