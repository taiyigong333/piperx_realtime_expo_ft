## uv客户端环境

```bash
ssh piperx
cd /home/cv/gcj/rl/baseline/realtime_expo_ft
git pull --ff-only
bash scripts/setup.sh client
uv run --project client --locked piper-x-collect --help
uv run --project client --locked python scripts/smoke_rpc.py
```

项目环境由uv维护，客户端Python固定3.10；不安装JAX/Torch，不复用4090的虚拟环境。已有Pika ROS工作区不修改，遥操示教仍按原采集项目的现场流程启动。

本机GitHub HTTPS访问出现连接超时，SSH通道可用。需要重新获取子模块时可运行 `PIPERX_GITHUB_SSH=1 bash scripts/setup.sh client`，只为本次Git命令将GitHub HTTPS源转为SSH，不改仓库origin或全局Git配置。子模块固定提交使用浅克隆，uv按已提交的锁文件安装。

## 有线协议验证

先在4090运行，再在piperx运行；测试只构造mock机械臂和合成RGB，不使能或移动真实硬件。

```bash
# 4090
cd /data/gcj_data/rl/real_time_expo_ft/code
uv run --project server --locked python scripts/smoke_network.py server \
  --host 192.168.50.2 --expected-peer 192.168.50.1 --steps 90
```

```bash
# piperx
cd /home/cv/gcj/rl/baseline/realtime_expo_ft
uv run --project client --locked python scripts/smoke_network.py client \
  --host 192.168.50.2 --steps 90
```

脚本验证任务协议、动作回传、图像数组、回合终止和render，并在服务端核对实际对端IP。结果分别写入两台机器的 `runtime/validation/network_server.json` / `network_client.json`，验证后进程正常退出。

## 真实运行配置

- 模拟客户端连接配置：`configs/client/mock.wired.yaml`。
- 真机客户端配置：`configs/client/piperx.wired.yaml`。工作空间与真实成功检测器暂为空，必须由现场配置，程序会拒绝未经配置的真实运动。
- 4090学习器配置：`configs/server/experiment.wired.yaml`，只监听192.168.50.2，数据和权重仍待提供。
- 客户端本机采集配置位于被Git忽略的 `configs/local/collection.yaml`，相机参数位于同目录；输出为 `/home/cv/gcj/rl/data/realtime_expo_ft/raw`，初始批次1，自动起始运动关闭。采集前人工确认新批次与现场状态，不能沿用4090的/data路径。

正式采集先完成硬件预检；真机策略执行前完成现场工作空间、成功判定和操作员复位流程。下面仅列未来启动命令，本次部署不执行真实硬件流程：

```bash
# piperx，现场配置完成后
bash scripts/collect.sh configs/local/collection.yaml \
  --teleop-config third_party/collector/configs/teleop/pika_sense_piper_x.example.yaml
bash scripts/client.sh --config configs/client/piperx.wired.yaml --allow-motion
# 4090，数据/权重和资产准备完成后
bash scripts/server.sh rl --config configs/server/experiment.wired.yaml
```

维护时先提交代码到主仓库，再在另一端 `git pull --ff-only` 并运行对应 `setup.sh`。不要使用submodule update --remote漂移固定版本。真实控制使用交互终端；断线后按操作说明检查现场再重启客户端，不设置无人值守自动重启。
