## 阶段与验收

1. **工程搭建**：主 Git 仓库 + 固定子模块；Python3.10/3.11环境隔离；文档和可执行入口。
2. **软件联调**：动作拒绝/失联锁定、终止后保持、RGB与位姿转换、上游 RPC 回环。合成数据验证不能替代真机测试。
3. **训练栈验证**：GPU可见，JAX/Optax实际执行一次小算子更新；算法模块导入、上游 replay 变换/采样和 RTC delay/prefix 控制流通过。不加载完整模型时不声称完成 pi0.5 训练。
4. **真实示教准备**：用户提供数据与权重。选择成功示教，按 episode 划分训练/留出集，核查时间对齐、任务指令、米制RPY、夹爪宽度、图像颜色与相机身份。版本化数据 manifest、资产、初始 checkpoint。
5. **RTC-SFT**：固定随机种子42，初始 batch4，先跑1个训练更新并保存/恢复 checkpoint，再决定正式步数。检查 loss/lr/梯度有限性、显存峰值、采样轨迹；不得直接从零配置启动长训练。
6. **现场执行**：先只读预检，再保持动作、受限单步、短chunk；实测30Hz、VLA推理p50/p95、网络往返、相机年龄、执行误差。`delay=ceil(p95_latency_s*control_hz)`，并保证 delay<=replan_steps<16。
7. **在线RL**：先可靠的现场成功检测与人工复位；单卡 episode 更新，保留在线replay和checkpoint，监控 success、return、loss、lr、边界拒绝次数。当前约48GB显存仍须测量 LoRA + critic + target 的实际峰值。
8. **评估**：在相同任务分布下比较 RTC-SFT 基线和 Real-Time EXPO-FT；固定回合数/随机种子，报告成功率、机器人在线分钟数、延迟和失败分类。达到论文提升需真实实验支持。
