## 数据同步与转换

机器人和服务器不要求共享文件系统。采集完成、文件关闭后再同步完整的 batch，禁止同步正在写入的 .staging/partial 文件。数据存于 code 之外，或使用已忽略的 data/；禁止提交原始数据、视频、模型。

EXPO 格式转换和统计命令见 README。LeRobot兼容导出：

```bash
uv run --project server --locked piperx-convert --format lerobot --input /绝对路径/raw \
  --output /绝对路径/lerobot_v1 --batches 2 3 4 --confirm-successful-demos
```

LeRobot原转换器保留其实现与验证边界；正式训练推荐使用本项目严格校验的 EXPO 路径。

## 双端启动与恢复

- 默认模型服务器只绑定127.0.0.1，用于当前单机模拟；双机时显式配置服务器 host 与机器人 server_host，同步端口8103。
- 已提供 `.wired.yaml` 配置：4090监听192.168.50.2:8103，piperx从192.168.50.1经有线网连接。不要在双机运行时误用127.0.0.1的单机示例。
- 双端任务指令、控制频率、episode长度必须一致。修改相机身份需要重新采集/验证，而不能只改模型键名。
- 首先完成 RTC-SFT；RL 的 rtc_weights 指向其 `<step>/params`。eval_checkpoint_dir 指向在线RL run的 checkpoints 根目录。
- 启动器默认拒绝覆盖已有运行目录；确认断点对应相同配置后使用 --resume。
- 真实客户端每回合要求操作员输入 READY。不会自动调用 SDK reset()；电子急停恢复应使用原控制工具并现场确认。
- 连接中断后客户端停止并退出；本项目启动器已禁用上游自动重连重发，服务器会退出。检查现场后按最后完整checkpoint/replay恢复两端，不可把断线前的action队列直接重放。
- 模拟客户端只有结构/协议验证能力，不提供真实成功奖励；不能用它生成有意义的RL学习结论。
