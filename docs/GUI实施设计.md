# 真机RL浏览器客户端实施设计与交接

## 目标与兼容边界

- 新增piperx本机浏览器GUI：双相机、真实/模拟状态、轨迹回放、自动判定、手动成功/失败、是否加入经验、回合步数和收录模式。检测阈值与硬件边界只读。
- 原CLI入口和默认服务器流程保留。GUI复核使用独立客户端入口及显式的服务器review模式，不默认改变已有脚本。
- 上游EXPO/OpenPI固定源码不改；复核模式复用原模型、sampler、replay和更新方法，新增主工程回合控制流程。
- 当前RTC-SFT正在GPU上运行，开发不停止它、不启动真机RL、不访问真实CAN或相机。

## 必须保证的语义

1. 采集`T`个实际动作与`T+1`个观测，实际发送的绝对位姿/宽度为训练动作；终止后不多执行一步。
2. 自动结果与手动结果分别保存；有效结果优先手动。显式手动失败是终止失败，超时且未手动改标保持截断语义。
3. 整条轨迹复核前不能进入replay、不能触发模型更新。拒收轨迹只归档，不进入replay或成功池，也不增加接受经验的更新额度。
4. 接收后服务器回传ACK，GUI区分“已提交”和“已进入经验”；连接失败时不谎报入库。
5. 每回合复位需GUI确认；参数在下一回合生效。断线、操作页面失联或硬件异常锁定停止，不能自动复位清除。
6. 运行档案为独立HDF5/JSON，不冒充“全成功示教”；失败标签不能经原成功示教reader误转为奖励1。

## 已实现模块

- `review.py`：决定规则、指纹、整回合准入（轻量共享模块）。
- `client/recording.py`：有界异步HDF5记录，JSON审核/ACK元数据，轨迹下载及回放。
- `client/gui_control.py`：连接、复位、终止、复核和参数状态机。
- `client/gui.py`＋`client/web/`：本地HTTP服务与无构建依赖HTML/CSS/JS。
- `server/review_train.py`：独立review模式的在线回合驱动，复用原算法组件。
- 独立GUI配置、启动脚本、协议/准入/HTTP测试和数据流检查说明。

## 数据检查重点

检查离线原始示教、LeRobot导入、RGB/相机身份、单位、绝对/delta变换、WebSocket消息、动作与下一观测对齐、手动奖励、拒收过滤、replay成功池、磁盘恢复和异常断线。输出独立说明文档，区分软件通过与现场未验收项。

## 进度

已阅读固定上游循环：旧`EpisodeSink`在done时立即flush，无法直接支持事后拒收；因此GUI使用独立回合驱动。现有CLI保持旧循环。已确认当前GUI运行依赖可使用标准库HTTP＋现有Pillow/h5py，无需新增客户端框架依赖。

2026-10-31实施：已加入HTTP界面、异步轨迹归档、整条摘要核对、人工优先标签、拒收过滤、ACK与独立训练驱动。用户追加要求后，浏览器可选逐条复核/自动收录；原CLI及服务器默认循环保留。最大步数和模式按下一回合快照生效。
