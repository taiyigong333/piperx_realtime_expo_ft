
**W&B会随训练自动启动在线记录，无需另开服务。** 配置已引用服务器此前训练的凭据文件，项目为 `gongcj-beijing/piperx_realtime_expo_ft`。RTC-SFT与RL分别使用带 `_sft`、`_rl` 后缀的运行名称；训练启动后打开终端打印的W&B运行链接即可看曲线。

## 2. piperx：真机预检与现场准备

退出占用机械臂或相机的GUI、遥操、采集程序。在客户端执行：

```bash
ssh piperx
cd /home/cv/gcj/rl/baseline/realtime_expo_ft
uv run --project client --locked piper-x-collect preflight \
  --config configs/local/collection.yaml
```

预检通过后，确认以下现场验收已经完成：

- 成功检测正负例：抓住并抬起能成功；空夹、未抬起、张开夹爪不成功。
- 保持动作、受限单步和短动作块执行正常；工作空间与起点已确认。
- 真实模型与网络延迟已实测；当前 `delay=5` 是初始配置，需按实测调整，且不超过 `replan_steps=8`。

当前奖励规则：法兰高度高于 **0.281807m**、实际夹爪宽度在 **[0.0346, 0.0386]m**、目标宽度未要求张开，连续 **6个实际动作步**满足后奖励1并结束，否则奖励0。只读正样本已验证，现场负例尚需验收。

若要复查成功姿态的高度/实际宽度，先人工夹住目标并抬起，再执行以下只读命令：

```bash
uv run --project client --locked python scripts/check_success.py \
  --config configs/client/rotating_square.calibrated.yaml
```

**开始RL前将目标放回旋转装置，机械臂和夹爪恢复到任务起点。不要从夹持抬起的成功终态开始训练。**

## 4. piperx：启动真实执行客户端

在机器人现场的交互终端执行：

```bash
cd /home/cv/gcj/rl/baseline/realtime_expo_ft
bash scripts/client.sh \
  --config configs/client/rotating_square.calibrated.yaml \
  --allow-motion
```

**这一步会进入真实控制。** 每回合开始前程序要求输入 `READY`；确认目标已放好、机械臂处于起点且现场可运动后再输入。程序随后使能并执行策略，不会自动归位或复位物体。成功或达到200步上限后，人工复位并确认下一回合。

前约10个在线回合为上游预热阶段，可能暂时没有梯度更新。当前设置约每30条经验累计一次更新调用，在回合结束时执行；一次调用包含多次critic子更新。

## 5. 查看日志、停止与恢复

服务器另开终端查看loss、lr、success等标量：

```bash
tail -f /data/gcj_data/rl/real_time_expo_ft/runs/rotating_square_h30_20261030_rl/metrics.jsonl
```

RL模型及在线replay保存在同一run的 `checkpoints/` 下；W&B在线记录loss、lr、success等指标，终端和本地metrics.jsonl同时保留。当前在线交互预算为4000步、每2000步保存。网络或认证失败时先处理记录连接，不要默认为已经在线上传。

需要结束时，先在客户端按 `Ctrl-C`，确认机器人停止/保持，再停止服务器训练。网络断开、反馈过期或动作越界时停下检查，不自动重发历史动作，也不要直接放宽安全阈值。

恢复时，确认最后完整checkpoint及replay可用，在服务器执行：

```bash
cd /data/gcj_data/rl/real_time_expo_ft/code
bash scripts/server.sh rl --config configs/server/rotating_square.h30.yaml --resume
```

随后重新启动第4步客户端，按提示人工复位。恢复同一run时保持模型、数据资产和动作约定一致；新实验使用新run_name。评估命令及详细验收方法见[完整训练流程](Real-Time-EXPO-FT完整训练流程.md)。
