# 命令行在线强化学习

更新：2026-11-02（Asia/Shanghai）。不启动浏览器GUI，保留机器人电脑执行和4090模型推理。旧`client.sh`是原自动模式，不具备这里的人工审核与整批传输合同；使用新`online.sh`。

## 最小运行路径

前提：已完成原采集预检、现场安全空间/归位路径与成功检测正负例验收；RTC权重和归一化资产可用。停止占用相机/CAN的GUI、遥操等程序，8103只运行一个模型服务。不自动停止其他任务，也不由软件维护人员远程发起真实运动。

1. **4090终端**启动模型服务：

   ```bash
   cd /data/gcj_data/rl/real_time_expo_ft/code
   bash scripts/server.sh rl --config configs/server/rotating_square.cli.yaml
   ```

2. **机器人现场终端**先预检，再启动命令行：

   ```bash
   cd /home/cv/gcj/rl/baseline/realtime_expo_ft
   uv run --project client --locked piper-x-collect preflight --config configs/local/collection.yaml
   bash scripts/online.sh --config configs/client/rotating_square.calibrated.yaml \
     --record-dir /home/cv/gcj/rl/data/realtime_expo_ft/cli_episodes --allow-motion
   ```

3. 模型预热成功、终端显示`awaiting_reset`后，现场摆好目标并输入`READY`。程序执行固定低速归位→张开夹爪→等待新鲜宽度到位→开始录制/rollout。
4. 成功检测或单条安全上限结束本条；也可输入`end`提前结束本条。显示`review_pending`后输入`s`（成功）或`f`（失败）。人工标签优先，成功和失败都可进入训练经验。
5. 重复人工开始/审核，采够10条后才整批传输训练文件，随后加载经验、更新10次、保存完整模型，自动进入下一批的人工开始等待。默认3批，共30条。每次更新仍包含原算法UTD子更新；这组数值是可调整的起始配置，未代表真机调参结论。

程序从不自动输入`READY`。运行中的观测/动作仍需实时往返4090，这是模型推理通信；带最终标签的HDF5训练经验在本批采满后才上传。采集期服务器仅保留本条推理状态及每条摘要，不提前归档训练图像或加入经验池。

## 命令与急停

| 输入 | 行为 |
| --- | --- |
| `READY` | 仅等待开始时生效；现场确认后归位、张开并开始下一条 |
| `end` | 正常结束当前条，随后人工判定成功/失败 |
| `s` / `f` | 在待审核时分别标成功/失败，并收录有效完整轨迹 |
| `stop` / `Ctrl-C` | 立即停止当前控制、强制标本条失败；保留采集会话，下一条仍等待新的`READY` |
| `quit` / 输入EOF | 退出整个任务，不将未满批次自动交给训练 |

急停不会自动恢复运动。下一条先关闭旧控制连接，建立新的本地执行环境，由现场明确`READY`后重新归位。归位被急停时尚未录制，不虚构轨迹、不计数，重新等待现场确认。实际保持/阻尼停止行为沿用现有安全实现，必须现场验收。

有有效动作/观测前缀的急停轨迹标`manual_success=false`、最终reward=0、terminal mask=0，作为失败经验。若急停发生在首动作前，或最后动作无法取得配对后继观测，则保留失败档案、拒绝入池，但仍算本批的一条已结束轨迹；继续下一条。未知执行结果记在`incomplete_action`中，绝不伪造后继观测或自动重发动作。网络断开、归档失败等不可恢复故障仍安全退出，不能宣称无故障继续。

## 配置与计数

编辑`configs/server/rotating_square.cli.yaml`，或复制到被忽略的`configs/local/`维护现场实验参数：

```yaml
cli_batch:
  episodes_per_batch: 10
  rounds: 3
  updates_per_batch: 10
  replay_capacity: 10000
load_demonstrations: true
```

- **批次触发只看轨迹条数**，包括成功、失败和被拒收的急停条；不看轨迹有多少step。
- `episode_steps=200`仍是单条安全时限，可在机器人端配置调整；不会决定何时整批传输。CLI不使用`max_steps`截断整个会话；其上游兼容字段仍保留。
- CLI不再使用旧GUI的10条冷启动与每30step额度规则；每批有有效收录才执行指定更新次数，全拒收批次不更新。经验必须满足RTC采样窗口，否则明确报错，不伪造训练成功。
- 首批采集完成、整批传输核对后才加载示教和恢复历史经验。`load_demonstrations=false`可只用在线经验，要求`offline_ratio=0`，且在线经验足够采样。模型权重与归一化资产仍必须先加载。
- GUI兼容路径也推迟经验加载，但GUI自己的预算和更新规则保持不变。

## 数据命名、日志与恢复

新建CLI实验名默认以本机时间戳开头；机器人端会话目录、轨迹目录以及服务器原始批次目录都采用`YYYYMMDD_HHMMSS_ffffff_...`，记录本机时区。审核协议仍使用稳定UUID，正常经验恢复目录保留UUID，避免破坏原格式。

- 机器人端：`cli_episodes/<时间戳>_cli/<时间戳>_<UUID>/episode.hdf5`与`metadata.json`。
- 服务器：`runs/<时间戳>_rotating_square_h30_cli_v1_rl/checkpoints/collection_batches/<时间戳>_round0001/reviewed_episodes/<UUID>/`。
- 经验入池后：同run的`checkpoints/reviewed_episodes/<UUID>/`；完整模型和`review_state_<step>.json`每批保存一次，step仍为累计实际动作数，**不作为批次触发条件**。
- 实时日志：终端及该run下`metrics.jsonl`，包含原训练loss/lr/指标与实际`training/update_count`。

续训填终端打印的原实验名，去掉末尾`_rl`：

```bash
bash scripts/server.sh rl --config configs/server/rotating_square.cli.yaml \
  --resume --run-name 20261102_153000_123456_rotating_square_h30_cli_v1
```

上述名字仅示意，必须换成实际存在且完整保存的run。续训恢复模型/优化器及已保存边界内的审核经验；配置的`rounds`表示本次再运行多少批。未满批次只保留本地文件，不自动补传；模型未包含的服务端经验保留隔离规则。不要把旧GUI实验直接当成CLI模型质量验收。
