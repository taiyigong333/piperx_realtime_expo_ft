# 动作放宽、常驻相机与GUI续训

日期：2026-11-02（Asia/Shanghai）。本轮为软件修改、模拟验证与部署，不执行真实机器人运动、GPU训练或完整模型续训。

## 目标与参考

用户要求放宽运动限制，提供按钮/Esc停止并静止保持，相机常驻、仅rollout保存，并支持选择某次历史学习接续。参考piperx的`/home/cv/gcj/project/baseline_fast/openpi`：`configs/safety.yaml`、`hardware/robot.py`、`hardware/cameras.py`与`controller.py`，只读检查，不修改旧工程。

参考策略速度90%、单目标位移0.3m、旋转0.5rad、夹爪0～0.10m；参考停止锁存当前位置，反馈无效回退阻尼急停；相机在断开/停止后复用。当前工程保留既有每轴旋转检查及法兰表示，不能宣称与参考的SO(3)角度检查完全相同。

## 实现

- 正式客户端配置对齐上述速度/距离/夹爪范围，固定归位速度10%和工作区不改。
- 独立CameraStream只缓存每路最新RGB，GUI持有，CAN/环境/手动复位借用；GUI退出才关闭，原CLI保持环境所有权。数据记录仍从归位完成后开始，T动作/T+1观测合同不变。
- 按钮/Esc停止事件不等待env归位锁，发送锁协调保持与策略/归位命令。采用法兰move_p锁存，避免SDK对负关节起点裁剪；不自动使能或reset。反馈失败退回阻尼急停。
- 服务端历史实验列表和显式续训参数保留原run_name/输出目录/W&B，传递--resume，校验模型/复核状态配套。仅新的管理启动日志使用新ID。可追加动作预算；新GUI默认每完整回合保存，原训练快照不静默重写。
