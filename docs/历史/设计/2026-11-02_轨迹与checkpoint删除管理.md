# 轨迹与checkpoint删除管理

日期：2026-11-02（Asia/Shanghai）。用户要求新增删除轨迹/checkpoint功能，并明确轨迹只删本地档案，服务器训练经验和模型保留。

## 实施合同

- GUI“轨迹档案”增加轨迹删除、本地回收站、服务器保存点/命名版本清单与回收站。
- 默认删除是同盘rename至`.trash/<ID>/payload`；可恢复，不释放空间。永久删除需重新输入完整32位回收ID，才删除payload，保留小型receipt审计记录；不自动清空。
- 轨迹仅移动本地UUID目录；录制/待复核/已提交未ACK/待整批处理状态拒绝。客户端活动会话和手动机械臂操作期间拒绝变更，不停止任务来删除。
- GUI-RL保存点与同step review_state作为一组移动/恢复，分组失败回滚；经验、W&B和其他checkpoint保留。删除最新点会回退续训，删完不可恢复模型，恢复后重新可见。
- 管理范围还包含配置内RTC-SFT和models/releases命名版本；原普通SFT路径只读。来源路径由本机实验/配置推导，网页只传来源ID、对象名、回收ID，不接受任意路径。
- 服务器变更受原ServiceManager文件锁保护，检查所有已知GUI任务及配置模型端口；活动任务或端口存在即拒绝。base_weights/rtc_weights初始化引用保护，不能直接删当前基线。
- checkpoint按需异步扫描，普通2秒远程状态轮询保留上次清单，不重复遍历权重；不影响相机/控制循环。JS只用textContent显示标识，不插入路径HTML。
- 命名版本硬链接独立保留：删除原保存点不删除命名版本；仍有其他硬链接时永久删除不保证释放完整模型空间。删除文件不撤销模型已有学习影响。
